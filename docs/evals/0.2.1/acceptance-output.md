## Root cause and correction

In 0.2.0, `##.x/*` was accepted and its unclosed comment swallowed the following generated hide rule. An isolated Chrome reproduction showed display:block with the bad rule, versus display:none with the valid rule alone. The parser now rejects both CSS comment delimiters and reports them as unsupported.

The previous getState called mutating apply helpers. It now calls explicit readPrivacy/readProxy entrypoints and does not register proxy listeners. Shared permission/validation/status logic remains centralized; only explicit apply entrypoints can set or clear native controls. Normal background initialization, settings saves and rollback retain their mutating paths.

## Limits

These are bounded selector checks, not a complete CSS grammar parser. Status reads report a mismatch instead of silently repairing it; saving settings reapplies the requested controls. Initializing a newly started background still applies configured settings. Live native write spies cover Chromium; Firefox has shared unit coverage plus native read-back. Native optional permission dialogs, declared minimum browser versions, store signing, CRX generation, complete proxy transports, QUIC and CAPTCHA outcomes are not covered. The unsigned XPI is for temporary loading and requires Mozilla signing for ordinary permanent Firefox installation. Earlier release evidence remains unchanged under 0.2.0 and the root eval directory.
